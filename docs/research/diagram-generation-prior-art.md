## Answer

Every tool surveyed emits Graphviz DOT first; only three emit mermaid natively (dependency-cruiser `--output-type mermaid`, tach `tach show --mermaid`, pyreverse `-o mmd`), and none is a zero-dependency pure-Python import for `aa_ma` — the forge must write its own emitter (codemem already owns the graph and a pure-Python PageRank). The scoping heuristics that recur are: (1) collapse-to-package/directory depth, (2) hop-limited neighbourhood around an entry point, (3) include/exclude regex, (4) drop external/stdlib nodes by default, (5) cycle-only view. Import-level edges are the universal default for architecture views; call-level tools (pyan3, code2flow, Sourcetrail) self-describe as approximate and add `--depth`/`--upstream-depth` style collapse to survive. Mermaid's own renderer refuses above `maxEdges: 500`; the tools' defaults (`--max-bacon 2`, `--focus-depth 1`, `--depth 0`) imply usable diagrams sit far below that.

## Recurring scoping heuristics

Candidates for Ticket 3's prototype (module-collapse vs pagerank top-N vs `--scope` entry point), ordered by how many tools converge on them:

1. **Collapse to package/directory depth** — pydeps `--max-module-depth`, dependency-cruiser `--collapse N|regex` and archi reporter's `collapsePattern`, pyan3 `--depth 0` (modules), grimp `squash_module`, tach's module granularity by construction, Sourcetrail "group by namespace/package or file". This is the one heuristic dependency-cruiser recommends *instead of* depth truncation. Strongest candidate for the default View.
2. **Hop-limited neighbourhood around an entry point** — pydeps `--max-bacon` (default 2), dependency-cruiser `--focus` + `--focus-depth` (default 1), code2flow `--target-function` + `--upstream-depth`/`--downstream-depth`, pyan3 `--function`/`--namespace` + `--direction`, Sourcetrail active-symbol + depth slider. Maps directly to the proposed `--scope` entry-point mode; default hop count 1–2 everywhere.
3. **Include/exclude regex on module path** — pydeps `--only`/`--exclude`/`--exclude-exact`, dependency-cruiser `--include-only`/`--exclude`/`--do-not-follow`, madge `--exclude`, code2flow `--include-only-namespaces`/`--exclude-namespaces`, pyan3 `-x`, pyreverse `--ignore`. Universal; cheap; should be an orthogonal filter, not a mode.
4. **Externals/stdlib off by default, opt-in** — pydeps `--pylib`/`--include-missing`, madge `includeNpm`, dependency-cruiser `doNotFollow: node_modules` + typed `dependencyTypes`, grimp `include_external_packages` (squashed), tach separates externals into `check-external`, pyreverse `--show-stdlib`/`--show-builtin`. dependency-cruiser's typed-edge model (keep the edge, tag it `core|npm|local|unknown`) is the most useful for a lint that must say `UNKNOWN` not `PASS`.
5. **Reverse / reach and cycle-only views** — pydeps `--show-cycles`, `--reverse`; madge `--circular`, `--depends`; dependency-cruiser `--reaches`, `no-circular`; pyan3 `--cycles`; tach `map --direction dependents`; grimp `find_downstream_modules`. Cheap secondary views once the graph exists.
6. **Degree/centrality pruning** — only pydeps has it as a flag (`--noise-level` drops high-degree sources/sinks). PageRank top-N appears as a *context-budget* heuristic, not a diagram heuristic: aider ranks files "on a graph where each source file is a node and edges connect files which have dependencies" under a `--map-tokens` budget (default 1k); codemem's `pagerank.py` is an explicit "Aider-style" pure-Python port (`packages/codemem-mcp/src/codemem/pagerank.py:1-11`). No surveyed diagram tool uses PageRank to pick nodes — Ticket 3's pagerank arm has no prior art to copy and should be treated as the novel arm.

**Edge semantics default (b):** import-level everywhere an architecture view is the goal (pydeps, dependency-cruiser, madge, import-linter/grimp, tach, pyreverse package mode, pyan3 `--module-level`). Call-level tools (pyan3, code2flow, Sourcetrail) are the ones that carry "approximate"/"pretty good estimate" disclaimers and need `--depth`/`--upstream-depth` collapse to stay legible — because static call resolution in Python is unsound (dynamic dispatch, duplicate names) and produces far more edges. Import-level is deterministic, cheap, and is what layer contracts (`.importlinter`, tach) already reason about. Recommendation for Ticket 5: import-level for Component view; call-level only inside a scoped entry-point view.

**Pure-Python, no-new-dependency reuse (c):** none. pydeps needs `stdlib_list` and shells out to `dot`; tach pulls networkx+pydot; pyan3 and pyreverse are GPL; dependency-cruiser/madge are Node; import-linter emits no graph. grimp is already a dev dependency (`uv.lock:749`) but is not a runtime dep of `aa_ma`, so importing it would breach the map's standing constraint (`diagram-generation-map.md:11`). The forge-local path is codemem's index + `pagerank.py` (already pure-Python power iteration, though the module imports `tiktoken` at import time — `pagerank.py:19,39` — which an `aa_ma`-side reader would have to avoid via the stdlib-`sqlite3` route the map's option (a) describes).

## Readability ceilings

| Source | Ceiling / default | Cite |
|---|---|---|
| mermaid config | `maxEdges` "Defines the maximum number of edges that can be drawn in a graph." default **500**; `maxTextSize` default **50000** chars | https://mermaid.js.org/config/schema-docs/config.html |
| pydeps | `--max-bacon` default **2** hops ("includes only the modules that your module imports — not continuing down the import chain") | pydeps README |
| dependency-cruiser | `--focus-depth` default **1**; `--max-depth` "typically a terrible idea" — collapse or filter instead; archi reporter collapses to first path segment under `src/`, `packages/`, etc. | dependency-cruiser cli.md, options-reference.md |
| pyan3 | `--depth` default detail collapse levels 0/1/2/max; `--max-paths` default **100** | pyan README |
| code2flow | `--no-trimming` exists because trimming (drop unconnected nodes) is on by default | code2flow README |
| C4 model FAQ | no numeric element ceiling published; recommends level-4 code diagrams be "generate[d] on-demand using tooling" or not created at all because they go stale | https://c4model.com/diagrams/faq |
| GitHub markdown | no stated diagram size limit beyond mermaid's own | GitHub creating-diagrams doc |

No tool publishes a node-count ceiling; the only hard number is mermaid's 500-edge render refusal. The tools' defaults (1–2 hops, collapse to top-level package) are the practical ceiling and should be the prototype's starting parameters.
