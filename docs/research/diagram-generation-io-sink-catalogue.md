## Answer

A generic I/O-boundary View is feasible, and every one of the 9 languages can surface a qualified callee (`receiver.method`, `pkg.Func`, `crate::path::fn`) with small parser changes — verified live against ast-grep 0.42.1 for the 8 ast-grep grammars, and via `ast.unparse` for Python. Recommend **v1 = Python + TypeScript/TSX/JavaScript + Go**: Python needs only the Ticket 1 P2/P3 fix plus an import-alias map (~25 LOC); the JS/TS/Go call rules need one `has: {field: function, pattern: $CALLEE}` line each and the wrapper needs a `-call` branch with enclosing-function inference (~50 LOC shared). Rust, Java, Ruby, Bash follow with the same wrapper change and one rule each; Java/Ruby carry receiver and method in two metavariables rather than one. The catalogue itself should be a codemem-owned YAML data file keyed on `(language, category, qualified-symbol)`, with a second, lower-confidence tier of bare method names (`execute`, `query`, `exec`) for receivers whose type is a local variable. CodeQL's `*.model.yml` files are MIT-licensed and directly reusable as seed data for Java/JS; Semgrep's rules are not redistributable (Rules License v1.0), so only the *format idea* (`pattern-sources`/`pattern-sinks`) is borrowable.

## Catalogue

## Prior catalogues (Semgrep, CodeQL)

**Semgrep taint mode.** A taint rule has `mode: taint` and four operators; `pattern-sources` ("Any subexpression that's matched by the pattern you define is regarded as a source of tainted data") is required, `pattern-sinks`, `pattern-sanitizers`, `pattern-propagators` optional; each accepts any search-mode pattern operator inline, and sinks default to exact matching (https://docs.semgrep.dev/writing-rules/data-flow/taint-mode). There is no shared catalogue: sources/sinks are inline per rule, so extraction means scraping many rule files. **Licence blocks reuse**: the `semgrep-rules` repository is under the "Semgrep Rules License v1.0" (https://github.com/semgrep/semgrep-rules/blob/develop/LICENSE), which permits use "only for your own internal business purposes" and states "This license does not allow you to distribute the rules, or to make them available to others as a service" (https://semgrep.dev/legal/rules-license). A derived data file shipped in this plugin would be a distribution. Reuse only the *concept* (source/sink/propagator/sanitizer vocabulary); write our rows from library docs (done above).

**CodeQL.** Boundaries are abstract concept classes, one per language library: for Python, `Concepts.qll` defines `FileSystemAccess` ("A data flow node that performs a file system access, including reading and writing data, creating and deleting files and folders…"), `FileSystemWriteAccess`, `SqlExecution`, `NoSqlExecution`, `SystemCommandExecution` ("…executes an operating system command…"), `CodeExecution`, `Logging`, and `Http::Client::Request` / `Http::Server::RequestHandler` under the `Http` module (https://codeql.github.com/codeql-standard-libraries/python/semmle/python/Concepts.qll/module.Concepts.html). `RemoteFlowSource` is "A data flow source of remote user input" (https://codeql.github.com/codeql-standard-libraries/python/semmle/python/dataflow/new/RemoteFlowSources.qll/type.RemoteFlowSources$RemoteFlowSource.html). This class taxonomy (`FileSystemAccess`, `SqlExecution`, `SystemCommandExecution`, `Http::Client::Request`, `Http::Server::RequestHandler`, `RemoteFlowSource`) is a good category vocabulary for our View and maps 1:1 to the seven categories asked for (Env/secrets and MQ/cache have no dedicated concept — CodeQL models `os.environ` as a `local` threat-model source).

**CodeQL Models-as-Data is the reusable data file.** Library models are YAML "data extensions" with extensible predicates `sourceModel`, `sinkModel`, `summaryModel`, `typeModel`, `barrierModel`, `barrierGuardModel`; the Java/JS tuple shape is `(package, type, subtypes, name, signature, ext, input, kind, provenance)` (https://codeql.github.com/docs/codeql-language-guides/customizing-library-models-for-python/ — marked "currently in beta and subject to change"). Example, `java/ql/lib/ext/java.sql.model.yml`: `["java.sql", "Connection", True, "prepareStatement", "", "", "Argument[0]", "sql-injection", "manual"]`, `["java.sql", "Statement", True, "execute", "", "", "Argument[0]", "sql-injection", "manual"]`. Coverage today: Java `ext/` has 112 `*.model.yml`, JavaScript `ext/` has 28 (incl. `axios`, `aws-sdk`, `shelljs`, `rimraf`, `mkdirp`), Python `ext/` has 1 (`default-threat-models-fixup.model.yml`) — Python frameworks are modelled in QL code under `python/ql/lib/semmle/python/frameworks/*.qll` (≈100 files: `Requests`, `Httpx`, `Flask`, `FastApi`, `Django`, `Psycopg`, `Psycopg2`, `SqlAlchemy`, `PyMongo`, `Aiohttp`, `Stdlib`, …), so Python rows must be transcribed by hand or via a QL query rather than loaded from YAML. **Licence permits reuse**: github/codeql is MIT (https://github.com/github/codeql/blob/main/LICENSE). Caveat: MaD `kind` values are injection-oriented (`sql-injection`, `command-injection`, `path-injection`, `request-forgery`) — they mark *tainted arguments*, not *every I/O call*, so a `sinkModel` row is a subset of what an I/O View wants (e.g. `Files.readString` appears as `path-injection` but `fs.stat` may not appear at all). Use MaD as a seed for Java/JS, then widen from the official docs.

Recommended data shape for codemem (mirrors MaD but language-tagged and match-typed):

```yaml
- lang: python
  category: db
  match: call            # call | member | subscript | decorator | command | redirect
  symbol: sqlite3.connect
  tier: qualified        # qualified | bare-method
  source: https://docs.python.org/3/library/sqlite3.html
```
