## What went well
- **Gates caught real defects before merge.** §6.8 ran 21 times. The 4 re-runs in M15 found a WAL bypass and a trust-token flaw. Fence 3 (TESTS_VERIFIED) and fence 2 (DIAGRAM_VERIFIED, 25/25 edges) were live for the plan's whole second half.
- **TDD held up under audit.** In M14 the RED commit was shown to fail at its own commit, using a throwaway worktree, before the GREEN commit landed.
- **Prototype-first changed decisions.** 9 PROTOTYPE lines were logged. The M11 co-change threshold replay over 27 milestone PRs set the numbers by measurement, not by guess.
- **The release was clean.** The bump commit changed exactly the 5 files commitizen owns. The tag date equals `IMPACT_CUTOVER`, and a test enforces that.

## What went wrong
1. **A known defect went unchecked into the release.** The run-evals nested-worktree bug was logged at 10.9 (P3) and was not checked before M14. The release's eval summary scored 0 of main's 31 cases. Since evals are advisory, the release itself was unaffected, but the summary carries no signal. → **L-074**
2. **The release was nearly cut on the wrong date.** The plan assumed 2026-10-28; UTC passed midnight before 14.1, so the cutover moved to 2026-10-29. A late release would have made the code wrong.
3. **Sub-step sync slipped again.** Two Result Logs were written while their Status stayed PENDING (L-073), and a lesson was repeated (L-072). In both cases the gate, not me, caught it.
4. **§6.3 is blind on main.** M14 ran on the main checkout, so predicted-vs-actual saw only unpushed commits (changed=1). §6.8 had to be pointed at the full window by hand.
5. **The figures I gave were not checked before I gave them.** I made up a SHA (M13) and made two false CHANGELOG claims (M13.1). A reviewer caught each one.
