## What went well

- **14 milestones in ~5 days with a HARD gate on each**, every one approved by Ste after 9/9-style
  AC verification, and a release at M6 and M14.
- **Measure first, then decide.** Ticket 17 refused to pick an MCP budget policy without data; the
  13.1 prototype on a 2,481-file monorepo found that the planned "collapse to coarser" policy
  returns an *empty* diagram (482 edges → 0) and produced the guarded policy that shipped. Same
  pattern in M9 (the 120-edge band measured OVER at 289) and M14 (Tier 6 found vacuous-or-noisy,
  replaced by a scoped guard).
- **The review loop caught real defects**: a draw `--write` that silently overwrote a team's own
  architecture doc, unbounded `hops` that could hang the MCP server, an unread §13 reported as
  `edges=0`, and the private-name leak. All fixed RED-first before their gates.
- **Test discipline**: 43.8% of inserted lines are tests (up from 35% in the last retro), with
  mutation checks on the new guards.

## What to improve (with the evidence)

1. **Private data reached a public repo** (L-029). Measurements of `medical-research-skills` were
   kept to counts in `reference.md`, but directory names were written into prose Result Logs and
   pushed; the §6.8 security auditor caught it, not the author. HEAD was scrubbed; 5 public commits
   still carry the names (Ste chose no rewrite). The rule is now a staged-diff grep before every
   commit that follows an external measurement.
2. **The RED-commit shape needed two lessons** (L-028 stubs tie the auditor's clock; M13 13.4 had
   to re-split a RED commit that swept in a context-log edit). Commit tests with an explicit path
   list, never `git add -A`, when the commit is RED.
3. **Count claims drift silently.** The §XI prompt template listed 12 outputs for five releases;
   the "12 MCP tools" count sat in five docs. Both are now guarded by tests — prefer a guard test
   over a sweep whenever a number is written in prose.
4. **A `/double-check` after "done" still found gaps** — four routes to the unshipped
   `/codebase-deep-dive` survived the M13 named-set rewire because the set was enumerated from
   the plan's estimate, not from a grep of the whole tree. Enumerate by grep, then decide.
