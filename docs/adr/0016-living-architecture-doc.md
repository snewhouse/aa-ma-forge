# 0016. The living architecture doc: generated `docs/architecture/` checked for drift in CI

**Status:** Accepted
**Date:** 2026-09-24
**Deciders:** Stephen Newhouse (sole maintainer)
**Tags:** `codemem`, `diagrams`, `docs`, `ci`, `architecture`

## Context and Problem Statement

Hand-drawn architecture diagrams go stale the moment the code moves, and nothing
notices. diagram-generation M1–M5 built the pieces to generate them instead: a
code graph with import and call edges (codemem schema v3), layered cuts and a
mermaid emitter (`codemem draw`, M3), a plugin-surface extractor over the
`claude-code/` markdown (M4), and an authored captions sidecar (M5).

The question is: **where do the generated diagrams live, and what keeps them
current?** The primary reader is a new developer or reviewer orienting in the
repo, who reads markdown on GitHub without building anything.

## Decision Drivers

- The committed doc must never silently disagree with the code.
- Authored prose (captions) must survive regeneration and must not count as drift.
- A provenance stamp (sha, date) is wanted, yet a byte comparison against a
  volatile stamp fails on every commit.
- A consumer repo without an index must not be blocked by a check that could not run.
- No new runtime dependency (no `yaml`); CI cost must stay small.

## Considered Options

1. **Commit the generated docs; a dedicated CI job regenerates and compares.**
2. **Commit a JSON export of the graph** and compare that.
3. **Do not commit docs; render on demand** (explorer / `codemem draw` only).
4. **Fold the check into the existing `codemem-smoke` job.**

## Decision Outcome

**Chosen option: 1 — generated, committed `docs/architecture/`, checked by its own `architecture-drift` job.**

- **Registry, not a hardcoded list.** `codemem.draw.views.VIEWS` maps a name to a
  `ViewSpec(output_path, title, generator, level, scope, summary, applies)`.
  `registered_paths(repo_root)` returns the views that apply to *this* repo.
  Registered now: `README.md` (index; the `@start` caption is its landing line),
  `component.md` (L2, the whole repo, both edge kinds, tests excluded), and
  `plugin-surface.md` (only where `claude-code/` exists; it lists dangling
  references and orphans under the diagram). `io` joins at M9 without a contract change.
- **CLI.** `codemem draw --write` regenerates every registered view;
  `codemem draw --check` compares. Bare `codemem draw` stays the M3 stdout emitter.
  `--write`/`--check` refuse `--level`/`--scope` (exit 2).
- **Line 1 is a stamp:** `<!-- generated by codemem draw @ <sha> on <date> -->`.
  An HTML comment needs no parser and is stripped on render. The sha is `HEAD` at
  regeneration time (so it names the parent of the commit that carries the file) and the
  date is UTC; neither is compared — `--check` requires only the stamp's **shape**.
- **What `--check` compares:** every line **except line 1** and **except the
  contents of the `<!-- captions -->` … `<!-- /captions -->` block**. Any other
  difference, including a hand-edit to the title on line 2, is `DRIFT` (exit 1,
  remedy `uv run codemem build && uv run codemem draw --write`). A caption-prose
  edit is not drift; an `@start` edit is, because its highlight is inside the
  mermaid fence. Masking is not a blind spot: every line inside the captions block must be
  a shape the generator emits (`- key: prose` or `Start here: …`, no raw `<` or `>`), or it
  is `DRIFT` too.
- **Captions are checked too.** A caption naming a path absent from `git ls-files`
  is `ORPHAN_CAPTION` (exit 1). The planned set is empty: caption only paths that
  exist. No tool ever deletes a caption.
- **No graph ⇒ `UNKNOWN`, exit 0.** Missing, pre-v3 or unreadable index. CI always
  builds one first; `UNKNOWN` is never reported as a pass.
- **Every write is confined** to `docs/architecture/` and can never touch the
  sidecar (`captions.check_generated_target`); all targets are checked before any is written,
  and a symlinked `docs/` or `docs/architecture/` is refused.
- **One regeneration command for this repo:** `scripts/regen-generated.sh` rebuilds the index,
  runs `codemem draw --write`, regenerates the plugin-surface golden and runs `--check`.
- **Caption prose is escaped** into one inert markdown line (`captions.escape_prose`).

## Pros and Cons of the Options

### Option 1 — committed docs + dedicated CI job
- Good: readable on GitHub with no build; drift is a named red X.
- Good: the index costs ~0.45 s to build (measured 2026-09-24 at 191 files), so regenerate-and-compare is cheap.
- Bad: every change that moves the graph needs a regeneration commit.

### Option 2 — commit a JSON export
- Bad: carries a generated artifact in git to avoid a sub-second command; readers still need a renderer.

### Option 3 — render on demand only
- Bad: nothing for the read-without-building reader; nothing to drift-check.

### Option 4 — a step inside `codemem-smoke`
- Bad: a stale-docs failure would surface as "codemem smoke test", misdirecting whoever reads the red X.

## Consequences

**Positive:**
- The committed architecture doc is provably current at every green commit.
- Authored captions and generated diagrams live apart and cannot overwrite each other.

**Negative:**
- Any change to imports/calls, `claude-code/` references, or `@start` requires
  `uv run codemem build && uv run codemem draw --write` and a docs commit, or CI goes red.
- A local `--check` against a stale index can disagree with CI (L-024): build first.

**Neutral:**
- ~30 s of extra runner time per push for the separate job (estimate from the map, Ticket 8).
